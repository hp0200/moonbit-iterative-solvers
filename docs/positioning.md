# 生态定位

## 项目身份

`moonbit-iterative-solvers` 是一个独立的新 MoonBit 开源库，面向稀疏线性方程组的迭代求解。

本库聚焦求解算法与数值抽象层，目标赛事方向为 MoonBit 黑客松方向四（高性能数值计算扩展）。

## 上游边界

本库与上游 `hp0200/moonbit-sparse-math` 是单向依赖的互补关系：

```text
上游：稀疏矩阵存储 + 数值诊断
              ^
              |
本库：数值抽象 + 迭代工作区 + 求解算法
```

- 上游负责稀疏矩阵存储与数值诊断。
- 本库不重复实现上述上游职责。
- 本库依赖上游公开能力；上游对本库零依赖。
- 本库不为上游矩阵增加包装类型，求解入口为包级函数。

已核实的上游公开仓库能力仅包括 CSR 稀疏存储（`SparseMatrix`、`from_dense`、`to_dense`、`spmv`、`transpose`，见 `csr.mbt`）、数值诊断工具（`is_diagonally_dominant`，见 `diagnostic.mbt`；`estimate_conditioning`，见 `diagnostic_ext.mbt`）、`test.mbt` 中的 10 个测试用例，以及 `.github/workflows/ci.yml` 工作流。本文不把这些之外的求解器、格式转换、乘法内核或导出能力归因于上游。

## 依赖拓扑定位

`Luna-Flow/luna-generic` 0.4.0 是本库的第三方依赖，提供 `@luna_generic.Ring`。上游同样引用该包，但上游自身不定义算术 trait。

本库定义的 `FieldSafe` 是独立 trait，不继承 `Ring`。求解器通过多重约束组合两者，避免把可编译性绑定到第三方 trait 的继承许可上。

本库只新增主库 `hp0200/moonbit-sparse-math` 与 `Luna-Flow/luna-generic` 两个依赖；不引入其它运行时第三方依赖。

## 能力定位

本期能力：

- 泛型能力层。
- 迭代工作区。
- 共轭梯度 CG。
- Jacobi 预条件。

本库不承担：

- CSR 或其它稀疏存储结构的定义。
- 稀疏矩阵格式转换。
- 数值诊断工具重实现。
- 上游矩阵包装类型。
- 未经实现与实测的导出层或性能承诺。

## 目标用户

- 已使用上游 CSR 数据、需要在 MoonBit 中求解稀疏线性系统的开发者。
- 需要可返回数值错误、而非依赖 panic 的迭代求解 API 的调用方。
- 需要在泛型代数约束下组织数值代码、但希望诊断量固定为 `Double` 的库作者。
- 面向 WebAssembly 场景、关注静态分派与产物边界的后续集成方。

具体后端导出能力属于后续规划；本期只有核心泛型路径。

## 与其它 MoonBit 数值项目的关系

本库的协作原则是：

- 可与上游在同一工作区中联合开发，但依赖方向保持单向。
- 可通过包级函数被下游调用，不要求下游复制矩阵包装类型。
- 不通过复制其它项目源码来补齐能力。
- 对未核实的项目边界使用 TODO 或明确的范围声明，不编造能力。

## 发布边界

开发期上游依赖可使用本地 path，发布前必须换回 registry 版本号，具体步骤见 `docs/publishing-checklist.md`。本库不把本地目录布局作为已发布包契约。
