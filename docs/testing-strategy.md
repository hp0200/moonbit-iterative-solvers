# 测试策略

本文只定义实现阶段的测试设计，不包含测试代码，也不声称当前已有测试。脚手架阶段不创建测试文件。

## 目标

- 验证 CG 与 Jacobi 在受支持实例上的数值正确性。
- 验证错误类别与错误上下文，而不是只验证“没有崩溃”。
- 验证残差满足公开容差契约，不依赖残差序列必须单调下降。
- 验证上游矩阵数据只读、输入输出所有权清晰、自别名行为确定。
- 验证 NaN 等非有限输入能够受控退出。

## 差分测试基准

### 参考解来源

参考数据由独立、成熟的数值环境离线生成，再以固定格式保存到仓库的 `testdata/`。测试运行时不在 MoonBit 进程内启动另一套求解器，也不把参考环境作为构建依赖。

每份 fixture 至少记录：

- 矩阵与向量的数据。
- 参考解或可用于计算参考残差的独立量。
- 容差定义与生成参数。
- 生成环境标识、生成器版本或提交标识。
- 矩阵类别与预期错误类别（若该 fixture 用于错误路径）。

`testdata/` 不由 `.gitignore` 忽略。参考数据一经提交即应可复现实验，不使用每次运行随机生成且无种子的输入。

### 差分断言

主断言对象是解回代后的残差是否满足容差，而不是要求解向量逐分量等于参考解。病态问题的解向量对舍入误差敏感，逐分量比较会产生不稳定的伪失败。

建议同时检查：

- 相对于右端项范数的残差判据。
- 相对容差失效时的绝对容差兜底（若公开契约采用组合判据）。
- 返回的成功/错误类别是否符合 fixture 预期。
- 返回的迭代信息是否与错误类别一致，例如超限错误不得标记为成功。

不在未实测的情况下写死误差上界、迭代次数上限或加速比。

## 断言原则

### 断言残差，不断言单调性

CG 的理论残差性质依赖精确算术、矩阵前提与实现路径。浮点实现、预条件和累积舍入都可能使残差序列出现局部回升。测试必须断言最终残差满足容差，禁止把“残差每一步都不增”作为通过条件。

### 不对病态 fixture 断言唯一解

病态矩阵可能存在多个几乎同样满足残差的数值解。对这类 fixture，以残差和错误类别为主，不以逐分量误差作为唯一判据。

### 错误路径断言分类

每个错误 fixture 断言具体错误类别，包括但不限于：

- 奇异主元。
- 内积 breakdown。
- 迭代超限。
- 维度不匹配。
- 方法前提不满足。

只断言“返回了错误”不足以防止错误分类退化。

## 自别名与所有权

公开求解入口采用只读输入与独立输出：

- `rhs`、初始解与矩阵数据在调用期间不被修改。
- 迭代开始前把需要变更的输入复制到工作区。
- 成功解使用与调用方输入分离的存储返回。
- 因此同一数组同时作为多个只读输入是被允许的；它不会与输出形成别名。
- 本期不提供“调用方预分配输出并原地覆盖”的入口。若未来增加，必须新开架构决定，并补充专门的自别名 fixture。

该契约需要显式测试：调用前后对输入做快照比较；把同一数组同时作为两个只读输入调用，确认结果与分离输入一致且输入未被改写。

## NaN 与特殊值

NaN 进入迭代时应受控退出：

- 不 panic。
- 收敛比较使用 IEEE 运算符，NaN 使 `<=`/`<` 为假。
- 在未命中显式零分母检查时，迭代继续到上限并返回“迭代超限”。
- 若 NaN 导致显式分母检查失败，则返回对应 breakdown 错误。
- 错误对象中的残差可以是非有限值，测试不得要求其满足普通有限值断言。

测试应覆盖右端项含 NaN、初始解含 NaN，以及迭代过程中产生非有限中间量的路径。后者的构造方式在实现阶段确定，但必须保持确定性。

## 正确性用例集

实现阶段至少覆盖以下类别；具体矩阵规模与参数在 fixture 生成时确定并记录：

- 小型、良态、对称正定矩阵。
- 对角占优或其它适合 Jacobi 的矩阵。
- 无预条件与 Jacobi 预条件的同矩阵对照。
- 不同右端项与初始解。
- 初始解已经满足容差。
- 零右端项。
- 迭代上限为零或极小值的边界行为。
- 病态但不一定立即 breakdown 的矩阵。

上述类别只定义覆盖意图，不在本文承诺示例数量或性能指标。

## 错误用例集

- Jacobi 对角含零的奇异主元。
- 产生零内积或数值对消归零的矩阵/向量组合。
- 迭代上限无法满足容差的病态矩阵。
- 维度不匹配的矩阵、右端项与初始解。
- 非对称或非正定矩阵进入 CG 的可观测失败。
- 含 NaN 的输入与中间量。

错误 fixture 的来源与预期类别必须在元数据中记录，避免测试结果依赖平台相关的偶然分支。

## 跨后端与确定性

- 分数、范数与容差使用 `Double`，不跨后端混用整数近似。
- 不要求不同后端逐位一致；使用统一容差判断数值一致性。
- fixture 与预期结果必须确定；若使用随机矩阵，必须固定种子并提交生成参数。
- 测试报告分别记录成功用例、错误类别用例与输入不变性检查，不能只看总通过数。

## 当前阶段边界

- 不创建测试文件，不写测试辅助函数。
- 不提交未经真实运行生成的结果数据。
- 不将上游测试数量或 CI 存在性当作本库已验证的证据。
- 不在测试策略中扩展本期算法范围。
