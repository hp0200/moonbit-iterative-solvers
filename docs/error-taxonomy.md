# 错误分类与数值失效语义

本库把数值失效视为求解调用的一种可返回结果，而不是进程级故障。公开求解入口的返回类型必须同时承载成功解和错误上下文；错误上下文至少应能让调用方区分失败类别，并保留可用于诊断的迭代信息与残差信息。

本文件只定义语义，不定义实现。具体错误类型名、字段和构造方式在实现阶段确定，但类别与处理原则不得弱化。

## 统一原则

- 数值失效不 panic，不通过异常或进程终止表达。
- 所有错误通过返回值向上传播，调用方可以局部重试、更换预条件或改走其它业务路径。
- 输入维度检查在进入迭代前完成；数值检查在产生相应中间量的位置完成。
- 误差阈值、残差范数与 breakdown 判据均使用 `Double`。
- 收敛判断使用 `<=`、`<` 等运算符，不使用 `compare`；`compare` 对 NaN 不提供结果保证。
- `div_safe` 在除数为零时返回 `None`，不执行除法，也不以 panic 表示失败。
- 错误对象的残差字段允许为 NaN 或无穷值；诊断输出不应把非有限值伪装成有限成功值。

## 失效模式

### 1. 奇异主元

**典型来源**

- Jacobi 预条件需要除以对角元素，而对角元素为零。
- 预条件构造过程中某个主元在所选数值判据下不可安全求逆。

**处理策略**

- 通过 `FieldSafe::div_safe` 检查分母；返回 `None` 时立即以“奇异主元”类别结束。
- 不执行接近无穷大的伪除法，不静默替换为任意正值。
- 返回的错误包含失败阶段、已执行迭代数以及当时的残差信息（若可用）。
- 调用方可改用无预条件路径或检查输入矩阵。

**为什么不 panic**

奇异主元是稀疏矩阵与预条件选择共同导致的常见可恢复条件，不是库内部编程错误。panic 会剥夺调用方换策略的机会，并使该失败在 FFI/导出边界难以稳定表达。

### 2. 内积 breakdown

**典型来源**

- CG 中搜索方向与矩阵乘积的内积为零，导致步长分母为零。
- 递推系数的分母为零。
- 数值对消使本应非零的内积归零。
- 中间量变为非有限值，后续比较无法给出有效收敛判断。

**处理策略**

- 分母为零时通过 `div_safe` 返回 `None`，归类为“内积 breakdown”。
- 对消归零不视为“已经收敛”，也不继续执行除零后的递推。
- 错误保留 breakdown 发生时的迭代数与残差；帮助调用方区分数值对消、预条件问题与迭代不足。
- 若 NaN 已进入迭代但尚未命中显式零分母检查，收敛判据因 IEEE 比较而为假，调用最终以“迭代超限”退出；不崩溃。

**为什么不 panic**

对消与 breakdown 是迭代法的一等数值现象。把它们作为错误值返回，可以保持调用流可组合，并让测试按类别断言而不是依赖崩溃。

### 3. 迭代超限

**典型来源**

- 矩阵病态，残差在给定容差和迭代上限内无法达标。
- 预条件质量不足或选择不适用。
- NaN/无穷值进入迭代，使收敛条件始终为假。
- 迭代上限设置过低。

**处理策略**

- 达到 `max_iter` 而未满足容差时返回“迭代超限”，并携带最终迭代数、最终残差与容差。
- 不把“达到上限”报告为成功，也不自行扩大上限。
- 病态矩阵若未触发显式 breakdown，按此类别报告；本库不把未经核实的条件数估计当作错误分类依据。
- NaN 进入迭代时沿用此路径退出，不触发 panic。

**为什么不 panic**

迭代上限既是用户参数，也是数值困难的表现。把它作为返回值能让调用方决定增加迭代、换方法或接受近似解；panic 会破坏这些选择。

### 4. 维度不匹配

**典型来源**

- 矩阵阶数与右端项长度不一致。
- 右端项与初始解长度不一致。
- 工作向量所需长度与输入维度不一致。

**处理策略**

- 在任何迭代写操作或分配依赖之前检查维度。
- 返回“维度不匹配”错误，并报告期望维度与实际维度（在可表达范围内）。
- 不尝试截断、补零或广播。

**为什么不 panic**

维度错误是调用方输入契约问题，错误值允许上层校验、转译或终止业务请求，而不会越过库边界终止整个宿主。

### 5. 矩阵不满足方法前提（对称正定）

**典型来源**

- 对非对称或非正定矩阵调用 CG。
- 曲率内积非正或为零，说明当前搜索方向不再满足方法前提。

**处理策略**

- 在产生曲率内积的迭代步骤检查其 `Double` 值；非正或不满足安全除法条件时返回“方法前提不满足”或相应的 breakdown 类别。
- 错误携带发现前提失败的迭代位置与残差。
- 不声称对所有非对称/非正定矩阵都能事先识别；未被检测到的问题将以 breakdown 或迭代超限暴露。
- Jacobi 预条件的存在不证明矩阵对称正定，不能替代前提检查。

**为什么不 panic**

方法适用范围是公开契约的一部分。以错误值报告可让调用方换用适用于非对称或非正定问题的路径，同时避免把用户数据问题伪装成库崩溃。

## 与上游测试示范情形的对应

公开仓库 `test.mbt` 仅示范了病态矩阵（`estimate_conditioning ill-conditioned`）；奇异主元与数值对消归零未出现在公开测试中。本库错误语义仍分别覆盖这些情形：

- 奇异主元 -> “奇异主元”。
- 病态矩阵 -> 可观测时报告 breakdown；不可观测时以“迭代超限”结束。
- 数值对消归零 -> “内积 breakdown”，不视为成功收敛。

该对应关系只约束本库错误语义，不扩展或改写上游能力。

## 返回值的诊断字段

实现阶段至少应让错误携带以下信息中的可用部分：

- 错误类别。
- 失败发生在输入校验、预条件构造还是迭代递推。
- 已执行迭代数。
- 当前残差范数或最后一次可计算的残差。
- 调用方提供的容差与迭代上限。

是否增加更细字段由实现阶段决定，但不得为了简化返回值而丢失错误类别或迭代位置。

## 非目标

- 不通过 panic 表达任何数值失效。
- 不把非收敛静默转换为“成功”。
- 不在未核实的情况下声称具备条件数诊断或自动修复能力。
- 不定义未经实测的误差上界或收敛保证。
