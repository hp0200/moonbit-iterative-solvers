# ADR-3：通过 FieldSafe 实现边界在设计上排除整数实例化

- 状态：已接受
- 日期：2026-11-19

## 背景

求解器在形式上可写为泛型算法，但收敛判据、残差范数、容差、右端项范数与 breakdown 阈值都属于实数诊断，不是矩阵代数的泛型部分。若让这些量随 `T` 泛型化，就需要在 `T` 上引入开方、绝对值、除法与特殊值语义，既扩大 trait 约定，也会让整数等离散类型产生没有数值意义的求解调用。

本库已有独立 trait `FieldSafe`，其唯一能力是可失败的除法。该 trait 的实现边界可以被用作“哪些类型有资格进入求解器”的类型系统闸门。

## 决定

- 本期只为 `Double` 提供 `FieldSafe` 实现。
- 不对任何整数类型实现 `FieldSafe`；整数类型调用求解器时应在编译期被类型约束拒绝。
- 所有实数量固定为 `Double`：残差范数、容差、右端项范数、breakdown 阈值及收敛比较均如此。
- 范数计算先通过 `ToDouble` 把泛型分量转换为 `Double`，再在 `Double` 上完成。
- 泛型参数 `T` 只承担向量与矩阵代数，不要求 `T` 提供开方或除法运算符；需要安全除法时使用 `FieldSafe::div_safe`。
- `Float` 实例化列入下一阶段，不在本期承诺。

## 依据

- 求解器的有效性依赖有理数、实数或浮点语义；“能相加”不等于“能求解线性方程组”。`FieldSafe` 把这种资格显式编码进类型系统。
- 整数除法会截断，且无法表达浮点收敛过程；若为整数实现 `FieldSafe`，类型系统会允许数学上不成立的调用。
- 统一使用 `Double` 诊断量可避免混合精度比较和泛型特殊值处理，也使收敛判据可以直接使用 IEEE 运算符。
- 将开方与范数放在 `Double` 侧，能把分数与浮点语义留在诊断层，不污染矩阵代数的 `Ring` 约束。
- 通过不实现 trait 而非运行时判断来排除整数，可使错误在编译期暴露，且不引入动态类型检查。

## 被否决的替代方案及其代价

### 为整数实现 `FieldSafe`，在除零时返回 `None`

代价：除零可以被捕获，但非零整数除法仍会截断，CG 的搜索方向与残差会被错误量化；类型系统会错误地宣称整数求解是受支持能力。

### 对所有 `Ring` 类型开放求解器，运行时检查实数能力

代价：失去编译期排除；需要动态分支、错误转换与不可达路径；整数、模运算或其它环类型会进入无意义的迭代流程。

### 在 `T` 上增加 `sqrt`、`abs` 与除法约束

代价：扩大第三方类型需要实现的能力面；“实数” trait 与 `Ring`、`FieldSafe` 形成第三套概念；整数可被误扩展，且浮点特殊值语义难以统一。

### 把所有诊断量保留为 `T`

代价：需要为泛型 `T` 定义比较、范数和特殊值处理，收敛条件无法统一为 IEEE 语义；混合精度与错误阈值也会失去固定锚点。

### 本期同时实现 `Double` 与 `Float`

代价：增加两种实例化的数值行为、测试矩阵与发布前验证面，超出本期四项承诺；未验证的 `Float` 路径容易形成隐性兼容负担。

## 后果

- 整数调用会在类型检查阶段失败，而不是返回运行时错误。
- 本期公开求解能力只有 `Double`；`Float` 的加入需要进入下一阶段并补齐差分测试。
- 下游若持有整数数据，必须先转换为受支持类型；本库不提供隐式转换。
- `ToDouble` 是本库数值抽象层的一部分，其转换语义必须在实现阶段单独审查，不能假设对所有 `T` 都无损。
