# ADR-4：转置矩阵-向量乘积由本库实现

- 状态：已被 ADR-7 取代（保留为历史记录）
- 日期：2026-11-19

## 背景

某些迭代方法需要对系数矩阵的转置执行矩阵-向量乘积。本库不能假设上游公开仓库已经提供该操作，也不能因为“普通矩阵-向量乘积存在”就推定转置版本存在。把缺失能力隐藏在调用路径中，会让后续算法实现依赖未经核实的接口。

同时，本库不拥有稀疏存储，也不应通过复制矩阵或引入包装类型重新实现一套存储层。转置乘积的归属必须与存储归属分开定义。

## 决定

- 转置矩阵-向量乘积的算法职责归本库，放在求解算法层，作为私有计算组件使用。
- 本库不假设上游提供转置乘积，也不把该假设写入公开契约。
- 转置乘积通过上游公开提供的数据访问能力完成；不复制上游存储结构，不新增矩阵包装类型，不在本库定义第二套稀疏存储。
- 若实现阶段发现上游缺少完成该操作所需的公开只读访问能力，应通过独立的上游 API 协作或新的架构决定解决，而不是读取、复制或改写上游源码来绕过边界。
- 该操作不改变公开 API 的矩阵所有权；调用方仍传入上游矩阵类型。
- 当前里程碑的四项交付不依赖转置乘积；本 ADR 先固定后续扩展的职责边界。

```text
// 签名示意，非最终代码
transpose_mul(matrix, input, output) -> result carrying success or numerical error
```

## 依据

- 已核实的上游能力清单不包含转置矩阵-向量乘积；本库不得对未核实能力作出隐含假设。
- 求解算法需要转置乘积时，其数值行为与错误语义应由本库负责，不能依赖未受控的外部实现。
- 不复制存储可保持上游为稀疏数据唯一来源，并维持单向依赖：本库依赖上游，上游零依赖本库。
- 私有计算组件可以随求解器错误语义一起演进，不扩大公开 API 面，也不引入包装类型。
- 当前 CG 与 Jacobi 范围不需要该操作，所以先记录归属而不把实现提前列入本期承诺。

## 被否决的替代方案及其代价

### 假设上游已提供转置乘积

代价：依赖未经核实的能力；一旦接口不存在或语义不同，后续算法无法编译或产生错误结果；错误会被错误地归因于求解算法。

### 定义转置矩阵包装类型并挂载乘法方法

代价：违反 ADR-1 的无包装决定；引入新类型身份、转换与生命周期问题；容易让本库滑向存储层实现。

### 在求解器中生成一份转置稀疏矩阵副本

代价：重复存储与额外内存峰值；转置存储的构建规则、数值诊断和生命周期变成本库职责；与“不重复实现稀疏存储”的边界冲突。

### 修改算法以完全规避转置乘积

代价：并非所有后续方法都能在不改变数值路径的情况下规避；可能牺牲收敛性质或需要另一套算法，不能作为通用所有权决定。

### 要求上游实现所有求解器专用的转置逻辑

代价：使上游承担算法层职责，扩大上游 API 面；本库的数值错误语义、预条件接口和版本节奏将受上游发布约束。

## 后果

- 后续需要转置乘积的算法在其自身里程碑内负责实现与验证，不把缺失能力转嫁给调用方。
- 验证时必须按数学定义对照转置乘积，不能只与普通乘积比较。
- 公开 API 不出现转置矩阵类型或额外存储类型。
- 若所需只读访问能力不存在，必须新开架构决定并保持单向依赖，不在本 ADR 下擅自跨过上游边界。
